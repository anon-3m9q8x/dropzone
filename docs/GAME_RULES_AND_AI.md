# DROPZONE — ゲームルール・CPU詳細仕様（正本補足）

`FPS_MASTER_SPEC.md` の第4章を補足する。定数の数値は必ず `data/game-config.json` に従う。

## 1. 計算と実行順序（厳格）

全ゲーム物理は固定tick `dt=1/60秒`。各tickで (1)入力（edge・holdを分離）(2)移動/衝突(3)プレイヤー物資・回復・リロードの状態遷移 (4)プレイヤー射撃 (5)Bot観測/5Hz意思決定 (6)Bot移動/射撃 (7)縮小円/区域ダメージ (8)死亡処理 (9)試合完了 (10)イベント返却。レンダリングとDOMの状態更新はこの後。戦闘中の瞬間ポーズは次のtickから完全停止。

### PRNG
`xorshift32(state:number):number`：`state ^= state<<13; state ^= state>>>17; state ^= state<<5;`を **符号なし32bit**で更新。`seed=0`を`0x6D2B79F5`へ置き換える。浮動乱数は `(state>>>0)/4294967296`。シードを変更する処理があれば `rngState` を更新。`Math.random()`はゲームロジックでは使用不可。日付からseed作成は新規試合生成の瞬間のみ許可。snapshotはseed/rngState両方を保持。

### 入力 edge
`fireHeld`は自動武器のみ継続判定。DMRは`fireHeld && !weapon.triggerPressedLastTick`で発砲。その後毎tick `triggerPressedLastTick` を更新。キーR/Q/E/jumpも入力アダプタで押下エッジとして生成。ポーズから戻った直後は全部離した状態からスタート。右クリックはADSのみ、射撃しない。

### 計測とイベント
弾消費時にプレイヤーの発砲時だけ `combatMetrics.shotsFired++`。rayが遮蔽ではない生存敵へ当たった時のみプレイヤーが撃った弾なら `shotsHit++`。実際に減らした盾＋HPをプレイヤーが与えた場合だけ `damageDealt`へ加算。結果画面で `accuracyPercent=shotsFired>0 ? round(shotsHit/shotsFired*100):0`。各tickのイベントはUI効果音/ログへ通知し、同じイベントを重複消費して二重計上しない。

## 2. コアマップの形と座標

- 地面：x,z `[-96,96]`、y=0、描画寸法192×192m。プレイヤーは `(x,0,z)` に足があり、目は `(x,playerHeight*0.94,z)`。
- 中央から半径90mを初期安全地帯とする。プレイヤーとBotの出現8地点は半径75m以内。
- マップ障害物（シードを使い位置・回転を固定）：「倉庫」4棟（底面12×8m、高さ5m）、「小屋」4棟（7×7m、高さ3m）、遮蔽箱12個（1.5×4×1.6m）。建物は単なる箱として実装すると内部に入れないため、出入口の穴を構成する **4壁パーツ＋屋根** のAABB配列とする。すべてユニークid。プレイヤーの頭上は屋根との衝突判定を取る。
- 侵入可能通路は最小幅2.2m。スポーン判定とNavGridのwalkable判定は障害物の半径0.5m拡張領域を使用。
- 安全地帯外周での初期スポーン禁止、物資は最大50個。物資の出現地点が生成できなければ決定的な安全リストへ戻す。
- ミニマップはx,zをアリーナ中心から等比で2D射影。向きは北固定、プレイヤー矢印のみyaw回転。Botは可視かつLOSありの時のみ敵マーカーとして表示。隠れたBotの位置は表示しない。
- NavGrid：4mメッシュ、48×48セル。壁AABBを膨張して障害に登録し、最寄りの到達可能なセルへA*で移動。計算頻度は1Botあたり最大2回/秒、経路の再利用可。通路に詰まったら別候補点を選ぶ。NavGrid自体はシードから再生成。

## 3. プレイヤー操作と衝突

- 水平移動の固定速度はrun7/walk5/crouch2.8m/s。Sprint中はADS, reload開始, fire, heal不可。既に始まっていたreloadはsprint開始でキャンセル。立ち状態からしゃがみ状態へのカメラ移動は0.18秒。しゃがみ解除は頭上空間の余裕をチェック。
- ジャンプは地面接触中のみ、初速5.1m/s、重力9.81m/s²。空中再ジャンプ不可。着地前に画面外へ落ちないよう地面y=0を下限にする。
- プレイヤー円柱の2D半径0.35mと歩行高さでAABB衝突。壁への法線方向速度を0にし、接線方向を保持。立ち止まっている際の細かなガタつきを防ぐため1e-4mの許容差を設ける。
- 走行時、武器を持ち替えられるが射撃できない。照準中は走らずwalk扱いとし、視野角を75→60へ120msで変化。アニメーション不要設定では即時変更。
- 移動キー入力があると回復を中断。メニュー操作時にkeyup取りこぼしを防ぎ、ゲーム入力状態を全消去する。

## 4. 武器と被ダメージ

| パラメータ | AR | SMG | DMR |
|---|---:|---:|---:|
| 1弾基礎ダメージ | 22 | 14 | 46 |
| 1秒連射 | 8 | 12 | 2.2 |
| 装弾数 | 30 | 36 | 12 |
| 予備弾初期数 | 90 | 108 | 36 |
| 予備弾上限 | 180 | 216 | 72 |
| 再装填 | 2.1秒 | 1.8秒 | 2.5秒 |
| 最大距離 | 85m | 55m | 130m |
| 腰撃ち散布角± | 2° | 3.5° | 1.4° |
| ADS散布角± | 0.55° | 1.1° | 0.25° |
| 連射 | 自動 | 自動 | 半自動 |

- rayは位置+forwardをベースに各軸乱数角度を足す。優先度は `head/body/cover` ではなく**交差距離の最短**。遮蔽が頭より手前ならcover。後方の敵は当たらない。プレイヤー自身を常に除外。死亡済みBotは当たり判定から除外。
- Botの射撃でも発射間隔・残弾・最大射程・遮蔽検証を必ず適用。Botは照準時に散布角を難易度で加算（ユーザーの武器散布角は武器定数）。
- 算出ダメージは頭1.5×、胴1×、Shieldを先に吸収。20盾＋100HPへ基礎30の弾を当てたら盾0/HP90。shield50を50補給で上限50。メディキットは2秒完了で+35HP、消費タイミングは完了時。
- reload開始時に現在武器をロック、時間完了後に `min(magSize-magazine,reserve)` を装填。途中で持ち替え・走行・回復を開始するとキャンセル、弾は失われない。
- 誤クリックによるフレンドリーファイアはなし。プレイヤーとBotの間にはチーム概念なし。

|---|---|---|
| ammo-ar | AR予備+30（上限180） | AR未所持または予備上限 |
| ammo-smg | SMG予備+36（上限216） | SMG未所持または予備上限 |
| ammo-dmr | DMR予備+12（上限72） | DMR未所持または予備上限 |
| medkit | 1個追加（上限3） | 3個所持 |
| shield | shield+25（上限50） | shield50 |
| weapon-* | 空スロットに追加、埋まっていれば装備武器と交換 | 同種を所持、アクター死亡 |

- 取得した物資のみ`active=false`にする。装備武器と交換した場合は新しいLootエンティティを同地点に作成。weapon pickup は新規武器マガジン満タン・予備弾は`defaultReserve`、交換で捨てた武器の弾数は拾得データ内で維持すること。現行 `LootState` にweapon格納がないため、**交換時ドロップだけ** `LootState` に `droppedWeapon?: WeaponState` を追加する（contracts/types.tsに追記しておく）。
- 物資取得範囲は2.2m。候補2個の場合は距離最短、同距離はID辞書順。CPUもE相当の自動取得で公平に回収。無限弾薬は禁止。

## 7. Bot AI（FSM・感知・チート防止）

### 感知入力を制限する
`BotPerception` には「位置が視界内・視線が通る」対象だけを `visibleEnemies` として渡す。視認判定は距離<=42mかつ前方120°以内かつ `hasLineOfSight=true`、および該当アクターが生存中。非視認時の実座標は入力しない。射撃音が発生したときのみ30m以内の座標を2秒記憶。最後に見た位置は3秒で失効。数tick前にいた位置へ向かってもよいが、壁向こうの新位置を追尾するのは禁止。

### 決定優先順位
1. Zone外 (`distanceFromCenter > zone.radius-2m`) → move-to-zone。目的地は現在の円内部のナビ地点。
2. HP <40、Medkit>0、視認敵がいない → heal。
3. HP <30、敵を視認中、有効な遮蔽物がある → retreat。
4. visibleEnemiesあり → engage。対象は距離最短、同距離ならID順。
5. 弾が少ない (`magazine + reserve <= magazineSize/2`) または装備1つ → seek-loot。
6. 記憶している lastSeenPos / lastHeardPos が未失効 → patrol（最終位置へ移動）。
7. 他 → patrol。シードから目的地を定期更新、壁を無視した直線移動は禁止。

### CPU反応と戦闘
- 新規ターゲット初見時の反応遅延はeasy600/normal350/hard180ms。LOSが切れれば射撃停止・記憶に移行。
- 狙いは見えている対象の胸、時々頭ではなく**胸のみ**（CPUのヘッドショットが発生するのは自然な散布結果のときだけ）。難易度別の追加散布角easy±6/normal±4/hard±2.5°。CPUは武器定数のhipspreadと追加誤差を適用。
- 5Hzで意思決定し、移動とクールダウンは60Hzで積分。CPUが他CPUを撃つこともできる。自分は除外。
- 物資を拾える距離まで到達したら移動を止め、1tickで1個取得。HP低下時に弾数無限化やHP自動復元はしない。
- 隠れたプレイヤーの現在位置をCPUの経路生成に渡さないことをAIユニットテストで証明する（記憶期限超過の視認なしで追尾しない）。

## 8. 射撃訓練（勝敗なし）

- 40m×50mの別の静的射撃場。無効な立入りを防ぐ壁。ターゲット位置：静止 `(0,1,12)` `(−6,1,22)` `(6,1,32)`、移動はz=25m/x∈[−8,8]を速度2m/sで往復。
- 3武器を無料で切替（射撃場のみ無限の予備弾として**表示に「練習用無制限」と記載**）。`GameSession.training` にターゲット4個・命中数を保持する。装填数は通常通り有限（0になるとRで再装填、予備弾は減らない）。ターゲットに当てたらターゲットのヒット数を数える。障害物の裏に隠れたら命中不可。
- ストップウォッチは練習開始からの秒。練習場の終了時、BRの戦績を増やさずホームへ戻る。設定/感度を練習中に変更可（ポーズUIを開く）。

## 9. 性能・再現性

- sceneは同じ seedで同じマップと敵スポーンを再現。CPUの判断乱数は必ず `rngState` を進める。保存復帰後の画面と戦闘状況が復帰直前のものと等価であること。
- Three.js `dispose()` はジオメトリ、マテリアル、テクスチャ、renderer、音声、各イベントリスナーを漏れなく解放。画面復帰で二重RAFを生成しない。
- low/medium/highを設定可能、低品質では影を描かず視距離・装飾を削減。ただし**敵/遮蔽の当たり判定はどの品質でも同一**。
